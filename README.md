- src/ — исходные файлы проекта

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности данных: товар и покупатель.

Интерфейс `IProduct` описывает структуру товара интернет-магазина. Каждый товар содержит уникальный идентификатор `id`, текстовое описание `description`, ссылку на изображение `image`, название `title`, категорию `category` и стоимость `price`. Стоимость может принимать значение `null`, если товар недоступен для покупки.

Интерфейс `IBuyer` описывает данные покупателя, необходимые для оформления заказа. Он включает способ оплаты `payment`, адрес электронной почты `email`, номер телефона `phone` и адрес доставки `address`.

Тип `TPayment` определяет доступные способы оплаты заказа. Возможны два значения: `online` — онлайн-оплата и `cash` — оплата при получении.

## Модели данных

### Класс Products

Класс `Products` отвечает за хранение и управление каталогом товаров интернет-магазина.

Класс хранит:
- массив всех доступных товаров `items: IProduct[]`;
- товар, выбранный для подробного просмотра `preview: IProduct | null`.

Конструктор класса не принимает параметров.

Методы класса:
- `setItems(items: IProduct[]): void` — сохраняет массив товаров в модель;
- `getItems(): IProduct[]` — возвращает массив всех товаров;
- `getItemById(id: string): IProduct | undefined` — возвращает товар по его идентификатору;
- `setPreview(item: IProduct): void` — сохраняет товар для подробного просмотра;
- `getPreview(): IProduct | null` — возвращает товар, выбранный для просмотра.

---

### Класс Basket

Класс `Basket` отвечает за хранение товаров, выбранных пользователем для покупки.

Класс хранит:
- массив товаров корзины `items: IProduct[]`.

Конструктор класса не принимает параметров.

Методы класса:
- `getItems(): IProduct[]` — возвращает товары корзины;
- `addItem(item: IProduct): void` — добавляет товар в корзину;
- `removeItem(item: IProduct): void` — удаляет товар из корзины;
- `clear(): void` — полностью очищает корзину;
- `getTotal(): number` — рассчитывает общую стоимость товаров;
- `getCount(): number` — возвращает количество товаров;
- `hasItem(id: string): boolean` — проверяет наличие товара в корзине по идентификатору.

---

### Класс Buyer

Класс `Buyer` отвечает за хранение, изменение и проверку данных покупателя.

Класс хранит:
- `payment: TPayment | null` — способ оплаты;
- `email: string` — адрес электронной почты;
- `phone: string` — номер телефона;
- `address: string` — адрес доставки.

Конструктор класса не принимает параметров.

Методы класса:
- `setData(data: Partial<IBuyer>): void` — частично обновляет данные покупателя без удаления ранее сохранённых значений;
- `getData(): IBuyer` — возвращает все данные покупателя;
- `clear(): void` — очищает данные покупателя;
- `validate(): Record<string, string>` — выполняет проверку полей на корректность и возвращает объект ошибок, где ключом является поле, а значением — сообщение об ошибке.

Поле считается валидным, если оно заполнено. Метод валидации позволяет определить ошибки отдельно по каждому полю.

## Классы слоя Представления (View)

### Общие принципы:
- Каждый класс представления отвечает за свой отдельный блок разметки.
- Все компоненты интерфейса наследуются от базового класса `Component`.
- Классы представления не хранят в полях никаких данных и не содержать геттеров или методов `get...` для их получения. Все данные хранятся только в Моделях данных.
- Элементы разметки находятся с помощью `querySelector` строго внутри конструктора класса и сохраняются в его полях.
- Все слушатели событий устанавливаются один раз в конструкторе класса.
- Метод `render()` класса, вызываемый без передачи аргументов, возвращает корневой DOM-элемент разметки класса.
- В ответ на любое действие пользователя класс представления не принимает самостоятельных решений об изменении разметки, а лишь уведомляет об этом слой Презентера с помощью генерации событий через брокер событий `EventEmitter` или вызов обработчика, полученного в конструкторе.

### Классы карточек товаров (с общим родителем)

#### Базовый класс Card
Базовый абстрактный класс для всех видов карточек товаров. Выносит общий функционал для отображения товаров, от которого наследуются конкретные типы карточек.

Конструктор:
- `constructor(container: HTMLElement)` — принимает контейнер для отображения карточки.

Поля класса:
- `_id: string` — уникальный идентификатор товара;
- `_title: string` — название товара;
- `_price: number | null` — цена товара;
- `_category: string` — категория товара;
- `_image: string` — URL-ссылка на изображение товара.

Методы класса (сеттеры):
- `set id(value: string): void` — устанавливает идентификатор товара;
- `set title(value: string): void` — устанавливает название товара;
- `set price(value: number | null)` — устанавливает цену товара (если цена `null`, блокирует кнопку покупки и меняет текст на «Недоступно»);
- `set category(value: string): void` — устанавливает текстовое название категории;
- `set image(value: string): void` — устанавливает изображение товара;
- `set categoryColor(value: string): void` — устанавливает фон категории товара, используя модификаторы элемента с классом `card__category` из объекта `categoryMap`.

#### Класс CatalogItem
Отвечает за отображение карточки товара на главной странице в основном каталоге. Использует шаблон `#card-catalog`.

Конструктор:
- `constructor(container: HTMLElement, actions?: { onClick: (event: MouseEvent) => void })` — принимает контейнер и колбэк клика.

Генерирует события:
- `card:select` — при клике на карточку товара в каталоге для открытия модального окна.

#### Класс PreviewItem
Отвечает за отображение карточки товара в модальном окне предпросмотра с детальной информацией. Использует шаблон `#card-preview`. Инициализируется в Презентере строго один раз при старте.

Методы класса (сеттеры):
- `set description(value: string): void` — устанавливает текстовое описание товара;
- `set buttonText(value: string): void` — динамически изменяет текст на кнопке («В корзину» / «Удалить из корзины»);
- `set valid(value: boolean): void` — блокирует кнопку покупки, если у товара отсутствует цена.

Генерирует события:
- `cart:changed` — опосредованно через модель при клике на кнопку добавления/удаления.

#### Класс BasketItem
Отвечает за отображение краткой карточки товара внутри списка в корзине (шаблон `#card-basket`).

Конструктор:
- `constructor(container: HTMLElement, actions?: { onClick: (event: MouseEvent) => void })` — принимает контейнер и колбэк клика по кнопке удаления.

Методы класса (сеттеры):
- `set index(value: number): void` — устанавливает порядковый номер товара в таблице корзины.

### Классы форм (с общим родителем)

#### Базовый класс Form
Абстрактный базовый класс для всех форм в приложении. Выносит общий функционал валидации, управления кнопкой отправки и вывода ошибок.

Конструктор:
- `constructor(container: HTMLFormElement, events: EventEmitter)` — принимает контейнер формы и экземпляр брокера событий.

Методы класса:
- `render(): HTMLElement` — отрисовывает форму;
- `protected onInputChange(field: keyof T, value: string): void` — генерирует событие изменения конкретного поля ввода в формате `${formName}.${fieldName}:change`;
- `set valid(value: boolean): void` — управляет блокировкой кнопки отправки (свойство `disabled`);
- `set errors(value: string[]): void` — отображает массив ошибок валидации в интерфейсе формы через запятую.

#### Класс OrderForm
Отвечает за первый шаг оформления заказа: выбор способа оплаты и ввод адреса доставки. Использует шаблон `#order`.

Конструктор:
- `constructor(container: HTMLElement)` — наследует логику `Form`.

Поля класса:
- `_payment: string` — выбранный способ оплаты;
- `_address: string` — введенный адрес доставки.

Методы класса:
- `render(): HTMLElement` — отрисовывает форму заказа;
- `set payment(value: string): void` — устанавливает способ оплаты, используя модификатор `button_alt-active` для выделения выбранной кнопки;
- `set address(value: string): void` — устанавливает адрес доставки;
- `validate(): boolean` — проверяет заполнение адреса и выбор способа оплаты. При ошибках активирует вывод сообщений.

Генерирует события:
- `order:payment-changed` — при переключении способа оплаты;
- `order:address-changed` — при вводе/изменении адреса доставки;
- `order:submit` — при клике на кнопку «Далее» и отправке формы.

#### Класс ContactsForm
Отвечает за второй шаг оформления заказа: ввод контактных данных покупателя. Использует шаблон `#contacts`.

Конструктор:
- `constructor(container: HTMLElement)` — наследует логику `Form`.

Поля класса:
- `_email: string` — введенный email;
- `_phone: string` — введенный номер телефона.

Методы класса:
- `render(): HTMLElement` — отрисовывает форму контактов;
- `set email(value: string): void` — устанавливает email покупателя;
- `set phone(value: string): void` — устанавливает телефон покупателя;
- `validate(): boolean` — проверяет, что оба поля заполнены, при ошибках выводит предупреждения.

Генерирует события:
- `contacts:email-changed` — при изменении поля email;
- `contacts:phone-changed` — при изменении поля телефона;
- `contacts:submit` — при нажатии на кнопку «Оплатить».

### Класс модального окна

#### Класс Modal
Отвечает за управление отображением, открытием и закрытием модальных окон приложения. Не имеет дочерних классов и не может быть использован для наследования. Вся разметка внутри него является независимыми компонентами.

Конструктор:
- `constructor(container: HTMLElement)` — принимает контейнер модального окна.

Поля класса:
- `_content: HTMLElement | null` — текущий DOM-элемент контента, вставленный внутрь модалки;
- `_isOpen: boolean` — флаг текущего состояния (открыто/закрыто).

Методы класса:
- `open(): void` — открывает модальное окно (добавляет элементу с классом `modal` модификатор видимости `modal_active` и блокирует скролл страницы);
- `close(): void` — закрывает модальное окно (удаляет модификатор `modal_active` и возвращает скролл);
- `set content(value: HTMLElement): void` — динамически устанавливает переданный компонент в качестве содержимого окна;
- `clear(): void` — полностью очищает контентную область.

Генерирует события:
- `modal:open` — при открытии модального окна;
- `modal:close` — при закрытии окна (по клику на крестик или на оверлей вне окна).

#### Класс Gallery
Отвечает за отображение сетки каталога товаров на главной странице сайта. Является контейнером для размещения карточек `CatalogItem`.

Конструктор:

Методы класса:

#### Класс Basket
Отвечает за визуальное отображение содержимого корзины (списка выбранных товаров) и управление процессом начала заказа. Использует шаблон `#basket`.

Конструктор:
- `constructor(container: HTMLElement)` — принимает контейнер корзины.

Поля класса:
- `_items: HTMLElement[]` — массив разметок товаров `BasketItem` в корзине;

Методы класса:

Генерирует события:
- `basket:open-order` — при клике на кнопку «Оформить».

#### Класс Header
Отвечает за отображение шапки сайта, включая логотип, кнопку корзины и счетчик товаров.

Конструктор:
- `constructor(container: HTMLElement)` — принимает контейнер шапки.

Методы класса:
- `render(): HTMLElement` — отрисовывает шапку сайта;
- `set counter(value: number): void` — обновляет текстовое значение на счетчике количества товаров в корзине.

Генерирует события:
- `header:open-basket` — при клике на иконку корзины в шапке.

#### Класс Success
Отвечает за отображение модального окна успешного завершения покупки. Использует шаблон `#success`.

Конструктор:
- `constructor(container: HTMLElement)` — принимает контейнер для отображения.

Методы класса:
- `render(total: number): HTMLElement` — отрисовывает сообщение об успешном заказе и выводит итоговую списанную сумму.

Генерирует события:
- `success:close` — при клике на кнопку закрытия «За покупками!».

## События приложения

Взаимодействие слоев в приложении реализовано через события, которые делятся по источникам генерации:

### События Моделей данных (Model)

- `products:changed` — каталог товаров успешно загружен с сервера и записан в модель `Products`.
- `preview:changed` — в модели изменился (выбран) товар для подробного просмотра.
- `cart:changed` — состав корзины изменился (товар добавлен или удален).
- `buyer:errors` — модель `Buyer` зафиксировала изменение состояния валидации полей доставки или контактов.

### События Представлений (View)

- `card:select` — пользователь кликнул на карточку товара в каталоге (сигнал к установке превью).
- `order:open` — пользователь нажал кнопку «Оформить» в корзине.
- `order:submit` — пользователь заполнил Шаг 1 и нажал кнопку «Далее».
- `contacts:submit` — пользователь заполнил Шаг 2 и нажал кнопку «Оплатить» (сигнал к POST-запросу).
- `success:close` — пользователь нажал кнопку закрытия в окне успешной оплаты («За покупками!»).
- `/^order\..*:change$/` — регулярное выражение, отслеживающее ввод данных в поля формы доставки Шага 1.
- `/^contacts\..*:change$/` — регулярное выражение, отслеживающее ввод данных в поля формы контактов Шага 2.

#### Формы оформления:
- `order:payment-changed` — генерируется при выборе пользователем одного из способов оплаты (изменяет активный класс кнопки);
- `order:address-changed` — генерируется в процессе ввода адреса доставки в текстовое поле формы;
- `order:submit` — генерируется при клике на кнопку «Далее» на первом шаге заказа;
- `contacts:email-changed` — генерируется в процессе ввода email в поле формы контактов;
- `contacts:phone-changed` — генерируется в процессе ввода номера телефона в поле формы контактов;
- `contacts:submit` — генерируется при клике на кнопку «Оплатить» на втором шаге заказа.

#### Интерфейс и модальные окна:
- `header:open-basket` — генерируется при клике на иконку корзины в шапке сайта для открытия списка покупок;
- `basket:open-order` — генерируется при клике на кнопку «Оформить» внутри корзины;
- `modal:open` — генерируется в момент открытия любого модального окна;
- `modal:close` — генерируется при закрытии модального окна (по крестику или клику на оверлей);
- `success:close` — генерируется при закрытии окна успешного заказа по кнопке возврата к покупкам.
